\section{Software Infrastructure}
\label{sec:experiments_software_infrastructure}

\gls{dl} and \gls{rl} are inherently empirical fields, in which the effectiveness of a method is ultimately assessed through experimentation.
Experimental validation is therefore as important as the theoretical formulation of the method.
For this reason, particular attention is given to the implementation of \gls{car}.
The method relies on established libraries that provide efficient and widely used implementations of its main components.
The implementation is made publicly available as open-source software to support the objective and reproducible replication of the reported results.\footnote{\url{https://github.com/Maxalaar/Clustering_Agent_Latent_Space}}

\gls{car} is organized as a pipeline of five stages, shown in Figure~\ref{fig:car_pipeline}.
Each stage is an independent executable, and stages communicate only through artifacts written to disk.
This decoupling allows any stage to be rerun or inspected independently.
The parameters of each experiment are gathered in a single configuration object, described in Section~\ref{sec:experiments_configuration}.
Each stage also saves the configuration it used alongside its outputs.
Every result can therefore be traced back to the settings that produced it.

\subsection{Initial policy training}

The first stage trains the initial policy $\OriginalPolicy$ using RLlib \cite{moritz2018ray, liang2018rllib}.
RLlib provides a highly scalable implementation of \gls{rl} algorithms and supports a wide range of state-of-the-art methods.
It supports distributed training, allowing the computational workload to be spread across multiple processes and machines.

The use of RLlib allows \gls{car} to be applied to any environment implemented using the Gymnasium interface \cite{towers2024gymnasium}.
This provides a common interface for environments with different observation and action spaces.
This flexibility allows \gls{car} to be applied to a wide range of environments.

By default, the \gls{rl} algorithm used for the initial policy is \gls{ppo} \cite{schulman2017proximalpolicyoptimizationalgorithms}.
Other algorithms supported by RLlib, such as \gls{appo} \cite{espeholt2018impala}, \gls{dqn} \cite{mnih2013playingatarideepreinforcement}, and DreamerV3, can also be selected through the same configuration.

The policy and critic networks are implemented using PyTorch \cite{paszke2019pytorch}.
PyTorch provides efficient GPU computation and supports a wide range of neural network architectures.
This provides a standardized implementation that is compatible with the broader \gls{dl} ecosystem.

The output of this stage is a checkpoint containing the trained policy $\OriginalPolicy$.

\subsection{Trajectory dataset generation}

The second stage builds the dataset used to train the surrogate policies.
The distributed execution capabilities of RLlib are used to collect trajectories in parallel.
Multiple environment runners execute the original policy simultaneously, distributing the computational workload across the available resources.

The original policy is run in the environment, and the interactions between the agent and the environment are recorded.
For each step, the dataset stores the observation together with the parameters of the action distribution produced by the policy.
Trajectories are stored as Parquet files \cite{arrow}.
Parquet is a compressed columnar format widely used for large-scale data processing.
Its columnar structure allows data to be read efficiently and supports concurrent access from multiple processes.
This is particularly useful here because the datasets contain on the order of one million observation--action pairs and cannot be loaded entirely into memory.

\subsection{Surrogate policy training}

The third stage trains the surrogate policies using behavior cloning.
This stage therefore converts the original \gls{rl} problem into a supervised learning problem.
The surrogate policies are trained to reproduce the action distributions generated by $\OriginalPolicy$ from the collected observations.

The training procedure is implemented using PyTorch Lightning \cite{falcon2019lightning}.
PyTorch Lightning provides a structured interface for supervised training while remaining compatible with the PyTorch ecosystem.
It handles common training operations such as data loading, optimization, checkpointing, and GPU execution, while allowing the underlying neural network implementation to remain fully controlled.

Once training is complete, the stage produces a set of $n$ trained surrogate policies.

\subsection{Surrogate policy evaluation}

The fourth stage measures how faithfully each surrogate policy reproduces the behavior of $\OriginalPolicy$.
Each surrogate is wrapped so that it can be used as an RLlib policy and is then evaluated in the original environment.
Its mean cumulative reward over multiple episodes is compared with that of $\OriginalPolicy$.
Evaluation episodes are collected using parallel environment runners.

This stage provides the value of the \BehaviorReconstructionName.
It therefore verifies whether the surrogate policies adequately reproduce the behavior of the original policy before their latent representations are analyzed.
If a surrogate does not reproduce the original behavior sufficiently well, its training can be repeated before proceeding to the next stage.

\subsection{Latent space analysis}

The fifth stage performs the main analysis of \gls{car}.
The latent representations produced by the surrogate policies form the point clouds that are analyzed using clustering algorithms.

The clustering step relies on the cuML library \cite{raschka2020cuml}, which provides GPU-accelerated implementations of several clustering algorithms.
This significantly reduces the computational cost of clustering and makes it possible to analyze point clouds containing tens of thousands of representations.

The resulting partitions are used to compute the \ClusteringUniversalityName and the \AbstractionScoreName.
The outputs of this stage are the resulting metric values and the material required for the qualitative analysis presented in the following sections.
